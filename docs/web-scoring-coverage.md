# 实验功能与 React 网页覆盖核对

本表以 `experiment-report.md` 和 `scoring-checklist.md` 为准，核对课程得分点中具有用户操作语义的功能是否能在默认 React 网页完成。存储原子性、密码哈希、限频、资源隔离等服务端保证没有单独按钮，其证据仍由对应自动测试和评测结果提供。

## 本轮发现并补齐的网页缺口

- 未完成草稿原先无法保存，AI 按钮也会被完整题目 Schema 在浏览器端拦截。草稿现允许有界的部分字段；局部修改或全面审查条件不足时明确禁用并列出缺失原因，只有用户显式选择“补全整题并验证”才进入完整工作流。发布和验证继续使用严格题目 Schema。
- 命题表单原先只能通过高级 JSON 设置来源和作者，现已提供直接输入控件。
- 普通登录用户原先只能通过 API 注册语言，现可在“账户 → 评测语言配置”完成；管理员页复用同一控件。
- 实验允许普通用户管理题目和语言；普通用户的“资源”主导航集中承载这些入口。管理员顶部隐藏已被管理中心覆盖的“资源”，但保留 `/resources` 兼容路由；管理员中心继续展示角色、全站提交、审计、日志公开、删题和重置等特权功能。
- 做题助手现把输入框和最新回答放在前面，旧回答按轮折叠且每页最多 5 条；“新对话”在服务端建立上下文边界，保留历史任务和费用但不再继承旧内容。
- 题库、提交、管理员题目、用户、访问审计、角色审计和测试点列表现共用分页器。分页器提供首页、尾页、前后箭头及当前附近最多 5 页，并对一页、首段、中段和尾段做边界测试。
- 主导航下方新增按用户隔离的“进行中”任务标签，记录正在做题、编辑草稿、查看提交和 AI/验证任务。关闭仅移除入口；本地备份失败或版本冲突时才要求确认，重新进入页面会恢复入口。
- 命题草稿提供基础检查与完整验证两个等级。基础检查允许没有参考解的手工题发布并明确标记未执行输出校验；完整验证保留 oracle、随机对拍和 100% 卡错门禁。修改草稿后旧报告立即失效。
- AI 辅助以模式卡片区分局部修改、全面审查并修正、补全整题并验证。局部与审查 Patch 都以 Code Review 的并排/单列差异呈现，采纳使用草稿 revision 防止覆盖并发修改；题面按词、代码和 JSON 按行标出增删。
- 做题结果区显示当前用户在本题的完整分页提交历史，新提交立即刷新，pending 时轮询；详情往返恢复原题、所选提交和结果区位置。
- 日志查询统一使用服务端裁剪响应：本人/管理员显示原始运行日志，公开查看者只显示逐点状态和权限说明，不额外读取私有提交详情。
- 代码编辑器默认 14px，仍保留 14/16/18/20/24 手动切换。资源详情、用户资料、测试点和草稿修复入口只在用户点击后定位一次，后台轮询不会抢滚动位置。
- “我的草稿”和“AI 任务”分别使用 `draft_page`、`task_page`，每页 10 条并可归档。运行任务归档前取消上游连接，内容、用量、费用和幂等记录继续保存。
- AI 回答中的每个有效语言代码块都可先看 Diff；不匹配语言、疑似片段和大幅删除会警告。确认时再次核对编辑器基线，覆盖后可撤销。
- 命题失败仍保存 `candidate`；用户可零费用另存为部分草稿或从已完成阶段继续。恢复草稿不能绕过发布门禁。
- 限频按“同一用户、同一道题”独立计数。删题后的提交保留并标记，但退出统计和题库进度，同题号重建也不会恢复旧成绩。
- 提交列表和访问审计均落实一级筛选规则；审计筛选为空时网页不请求，接口返回 400。

## 权限与不可视为网页按钮的得分点

- 删除题目、修改角色、查看全站提交、重测、公开日志、访问/角色审计和重置数据只对管理员显示，后端同时执行权限校验。
- 普通用户仍能按实验约定创建/编辑题目、注册语言、提交代码、查看自己的完整提交及管理自己的命题草稿；题目公开日志后可查看他人逐点状态，但不能读取他人提交概要、源码、隐藏输入或标准输出。
- JSON 原子替换、SQLite 事务、bcrypt、HttpOnly Session、请求限频、任务恢复、命令 argv 安全和 runner 资源限制是操作后的服务端行为。网页能触发和观察结果，但不会提供关闭这些保证的控件。
- 动态语言注册不会下载或安装编译器，只登记受限命令模板；工具需由服务器预装。
- 系统默认模型密钥属于本机运维配置，不是课程评分表中的用户操作；个人模型配置已覆盖 Advance R1–R4。真实供应商输出质量仍取决于所配置模型，mock 验收只证明协议和流程。
