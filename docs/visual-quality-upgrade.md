# 视觉精修与 AI 内容质量验收

本轮沿用 FastAPI、React 与现有题库，默认入口仍为 `http://127.0.0.1:8000`。
没有数据库迁移，不修改已有题目、用户模型设置或 Token 预算。

## 页面前后变化

| 原有表现 | 本轮表现 |
| --- | --- |
| 题面与代码左右分栏，手机隐藏其他标签内容 | 全设备纵向排列，吸顶快捷跳转，完整宽度编辑器 |
| 大量纯文字分隔 | 白底、浅蓝点缀、线性图标、轻阴影、统一圆角和字体层级 |
| 评测只展示文字结果和原始日志 | 结果徽章、通过比例、得分、可选测试点网格、耗时/内存、失败筛选和分页 |
| 搜索每次输入修改 URL | 组合输入保持本地，选词后提交；普通输入防抖，失焦/Enter 提交，清空立即生效 |
| 命题要求 JSON，没有统一正文排版协议 | JSON 字段内明确使用 Markdown/LaTeX，样例与代码保持原文 |

`var/visual-quality/`，测试产物不纳入 Git。

## 接口和评测事实

提交列表/详情的 `include_metadata=true` 响应新增 `evaluation`，旧字段和旧客户端保持兼容。
摘要字段包括 `status`、`verdict`、`score`、`max_score`、`executed_cases`、`passed_cases`、
`total_cases`、`all_passed`、`result_counts`。列表按批次读取测试记录，无逐提交 N+1 查询。

`score/counts` 是得分和满分；当前评测规则每点 10 分。因此 3 个测试全部 AC 为
3/3 测试点、30/30 分。数量从该次提交保存的数据恢复，不依据后来修改的题目推算。
CE 占位记录不计入已执行测试；pending/error、零测试、缺失或不一致的历史结果不会误判 AC。

做题助手附带本人提交代码、语言、规范摘要和允许查看的测试状态/耗时/内存，
不包含隐藏输入、期望输出、其他用户代码或密钥。当前代码与提交代码分别标注；
历史对话增加代码关联与结构化评测事实。会话/任务查询额外返回快照语言和提交编号。

## AI 协议与质量门禁

Prompt 升级到 `oj-2026-09-v3`。正文使用 `$...$` 与独立的 `$$` 公式块；外层仍为 JSON，
LaTeX 反斜杠按 JSON 正确转义。原始 HTML 继续禁用，链接和 KaTeX 信任边界不放宽。
未闭合流式公式保留文本；无效公式显示原文和格式提示。KaTeX 样式属性保留，避免自定义
错误组件破坏正常公式布局；兼容已有单行 `$$...$$` 写法。

服务端只检查正文的控制字符、分隔符和括号，不转换代码/样例。完整命题在复审前提供
候选 Schema 错误与完整 Schema，结束前执行现有参考解、oracle 和错误解验证。
局部修改复审后的确定性结构/排版错误最多一次定向修复，仍使用局部预算；修复后失败
保留失败状态，不自动再次付费。排版检查不是完整 LaTeX 解释器，具体命令由浏览器
KaTeX 验证并安全降级。

真实验收发现并修复了参考解误放入 `problem` 的问题：阶段边界将这个已知字段移至
正确位置，去掉题面对象中的非 Schema 字段并将处理反馈给复审。不会跳过代码执行验证。
同时明确错误解的反例应写入 `reason`，不得添加 `failing_input` 等未知字段。

## 验收方法与边界

- 浏览器 11 项流程通过：登录、中文组合输入与 URL 恢复、纵向布局、提交和测试点控件、
  AI 流式/恢复/取消、命题发布、局部修改采纳、草稿冲突、账户切换和响应式截图。
- 前端 10 项组件/备份测试通过；类型检查、Lint 和构建通过。
- 后端新增评测语义、上下文证据、数学文本检查、局部修复上限及错放字段恢复测试。
- 输入法自动验收采用真实 Chromium 中的组合事件，不等同于 Windows 系统拼音候选窗的
  人工验收；系统级输入法候选窗未完成独立人工确认。
- mock 保留慢流、心跳、截断、断流、429、超时、取消、重复请求、服务重启和权限隔离回归。

真实模型验收通过 `scripts/check_ai_experience.py --run-paid` 显式执行，读取已配置模型，
在临时数据库与题库运行。脚本默认覆盖 6 个助手场景、5 个局部/审查入口、新建整题和
完善整题；`--only` 用于有明确问题的助手复验，`--revise-fixture` 用于复用已验证的验收草稿。
所有真实结果、失败和用量保存在指定的本机 JSON 中，不提交配置、用户数据或临时数据库。

真实回答已正确识别 3/3 全通过、30/30 满分，以及历史上与当前代码相同的失败提交。
但一次复验仍错误地声称 20 亿超出有符号 32 位范围；已加入明确事实约束，不能据此
宣称模型推理绝对可靠。界面评测结论由服务端数据计算，AI 的解释不能改变评测成绩。
完整命题曾成功通过；完善整题的结构失败被门禁拦截，失败调用也计入验收用量。

- 前端：10 项组件/备份测试、11 项 Chromium 流程；类型检查、Lint、构建、Ruff、mypy 与差异检查通过。

- 完善整题第一次复验仍因 Schema 类型与额外字段失败。增加复审前完整 Schema 反馈后，第二次针对性复验使用一次定向修复通过门禁；没有修改校验标准。
- 新建整题：4 个样例、12 个测试、2 个错误解、20 次独立对拍通过；最终完善整题：5 个样例、10 个测试、2 个错误解、40 次独立对拍通过。

- 实际自动代码审查发现 AI 区域宽泛的 h3 样式会隐藏回答小标题，已缩小选择器并增加浏览器可见性回归；审查 COMMENT 与复审结论记录在 PR 中。

## 计划复核与难度标准化（2026-09-04）

原视觉与 AI 升级已通过 PR #22 普通合并到 `main`，合并提交为
`2e3751dbcdad7ca4cbd58c7c51221797f8ec5816`；[合并后 CI](https://github.com/jasonpiggg/Online-Judge-System/actions/runs/33865878061) 已通过。
纵向做题、评测控件、中文组合输入修复、统一评测事实、Markdown/LaTeX、真实模型验收与自动审查均已完成。
仍不能算作已通过的项目是 Windows 原生拼音候选窗人工确认，以及已记录的模型数值推理错误；
浏览器组合事件回归通过不能替代原生输入法验收，模型回答也不能视为数学正确性的保证。

本次追加难度标准化：

| 统一等级 | 判断依据 | 兼容旧值示例 |
| --- | --- | --- |
| 入门 | 输入输出、算术、条件与简单循环 | beginner、intro |
| 简单 | 单一基础方法，思路直接 | easy、basic、基础、初级 |
| 中等 | 算法选择与边界处理 | medium、intermediate、进阶、中级 |
| 困难 | 组合算法、较复杂证明或状态设计 | hard、advanced、高级 |
| 挑战 | 深入推导、多方法结合、严格性能优化 | expert、challenge、极难 |
| 未分级 | 尚未评定或无法识别的历史标签 | 空值、unknown、unrated |

- `src/oj/difficulties.json` 是唯一标准源；后端校验、AI Prompt v4、React 与兼容入口共用。
- 英文别名忽略大小写与首尾空格；旧数据读取时归并，不批量改写历史文件或重新推断题目等级。
- 新写入拒绝不受支持的自定义等级；草稿保存、发布、历史版本显示和本地备份恢复均使用规范值。
- 题库固定等级顺序，支持「未分级」筛选和旧 `difficulty=easy` 链接；徽章带颜色与文字，分级说明默认折叠。
- 命题改为固定选项，AI Schema 列出允许值；规范化失败任务的旧上下文，避免别名差异阻止恢复已完成阶段。
- 此轮没有新增付费模型调用，也没有提高预算或增加重试。真实模型用量沿用上方实际记录。
