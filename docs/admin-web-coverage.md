# 页面精修与管理员网页权限核对

## 文档要求与实际缺项

以 `docs/API.md`、`docs/scoring-checklist.md` 和实验报告中的权限定义为准。
文档要求题目完整信息与 CRUD、管理员查看用户和提交、重测、公开评测日志、角色管理、
审计、语言配置和实验数据重置。题号是题目详情的必需字段，不是仅在后台使用的标识。

核查发现：后端已有全站提交查询能力，但 React 的“我的提交”固定传当前用户 ID；
新版管理页没有题目管理与指定用户提交入口。题目删除、编辑、管理员重测虽已有分散入口，
也不能等同于管理员工作台完整。旧版 Streamlit 的验收记录不能替代新版网页覆盖情况。

## 当前网页入口

| 功能                   | 入口与实际内容                                                                                         | 权限边界                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| 题号与完整题目信息     | 管理 → 题目 → 查看详情：题号、作者、来源、难度、限制、样例/测试数量；展开完整题面、测试数据、原始 JSON | 管理工作台仅管理员显示；沿用原题目 API 权限    |
| 题目创建、编辑、删除   | 管理 → 题目；编辑进入已有命题草稿流程；删除要求再次输入题号                                            | 后端删除检查管理员；发布沿用验证门禁           |
| 日志公开性             | 题目详情 → 公开日志，保存中禁用重复操作，失败恢复原状态                                                | 后端仅允许管理员设置；不公开其他用户源码       |
| 全站提交与指定用户提交 | 管理 → 提交；或用户行 → 提交记录；支持用户 ID、题号、执行状态、通过情况和分页                          | 服务端拒绝普通用户 `all_users` 和跨用户范围    |
| 提交代码与逐点评测     | 提交编号/结果 → 详情；展示用户名、语言、源码、编译诊断和评测控件；返回保留筛选条件                     | 仅本人/管理员可查看私有提交详情                |
| 管理员重测             | 提交详情 → 重新评测；执行中禁用，结果自动更新                                                          | 后端管理员检查不变                             |
| 用户列表、资料与角色   | 管理 → 用户；可按用户名或 ID 搜索，查看资料、统计、加入日期、禁用/升降角色                             | 后端管理员检查；最后一位管理员不能降级或禁用   |
| 创建普通用户/管理员    | 用户页 → 创建用户                                                                                      | 创建管理员接口验证角色                         |
| 语言配置               | 管理 → 语言；查看限制、扩展名、编译/运行命令，注册或更新配置                                           | 沿用既有 API 规则，不扩大命令模板能力          |
| 访问审计               | 管理 → 访问审计；按用户/题号筛选，显示允许/拒绝，支持分页和关联跳转                                    | 管理员限定                                     |
| 角色审计               | 管理 → 角色审计；操作人、目标用户、变更前后角色、时间、分页                                            | 新只读接口 `/api/logs/roles/`，管理员限定      |
| 实验数据重置           | 管理 → 系统设置；折叠危险操作并要求输入 RESET                                                          | 沿用后端管理员检查，不在真实用户数据上执行验收 |

“系统默认模型与密钥配置”仍按既有 API 文档通过服务端配置流程管理，没有新增网页密钥管理权限；
个人 AI 配置在账户页。做题助手私有会话也不因增加全站评测查看入口而扩大访问范围。

## 排版与交互变化

- 导航栏加入线性图标、浅色选中面板、账户头像与角色标识；主体与导航内容采用一致的居中宽度。
- 题库题号独立成列；表头与内容行共用 grid 列宽、间距和内边距，难度/状态按列居中。
  手机将题号与标题上下放置，保留所有信息；长题号、标题与标签可换行。
- 统一筛选区、列表表头、分区、管理标签、用户角色徽章、统计卡与命题草稿列表的样式。
  页面和编辑器保持白色，没有新增宣传区或大面积深色背景。
- 正文基准由 18px 调整为 16px，页面标题、评测大数字和做题分区标题同步收紧；原本已经是
  14–16px 的辅助文字、表格、表单控件、按钮、代码和测试点标签保持原字号。
- 用户与审计搜索复用组合输入保护；管理员提交详情返回保留 URL 中的用户/题号/分页条件。
- 管理数据读取显示加载/错误/空状态；写请求执行中禁用重复操作，公开日志开关提供即时反馈。

## 验收与数据保护

- 新增浏览器流程验证长题号列对齐（按真实元素坐标比较）、1440/1024/390px 页面无横向溢出、
  主导航点击区至少 44px；各页面与管理员四个主要视图保留真实浏览器截图。
- 隔离数据库创建学生账号和提交，完成用户资料 → 指定用户提交 → 源码/评测 → 重测 → 返回与刷新；
  完成题目详情、日志公开、命题草稿、禁用用户与角色审计。
- 新增后端回归验证用户名补充字段不改变旧 envelope、不泄露列表源码、跨用户越权仍拒绝；
  用户搜索使用绑定参数和字面匹配；角色审计验证分页、边界与管理员权限。
- 截图保存在本机 `var/interface-before/` 和 `web/test-results/`；测试使用独立题库/数据库。
  本轮不修改正式用户角色、不删除正式题目、不重置正式数据、不调用付费模型。

完整测试与 CI 结果记录在对应 PR 的实际自动审查和交付评论中。
