## 容错改进

- 首稿 JSON/Schema 出错时，将字段路径与错误类型传给已经安排的第二阶段复审修正，
  不再在第一阶段提前失败；最终结果仍必须严格通过校验。
- 完整命题首稿的 Python 代码先做 AST 语法检查，不执行这些代码；诊断同样供复审修正。
- 强调输入必须满足题目的字符集合、格式和范围，不能把域外输入当成“负样例”。
- 用户未限定具体题型时优先选择紧凑输出的设计；不静默放宽用户明确给定的要求。
- 显式告知模型程序输出上限，避免生成无法运行的大规模完整轨迹。
- 阶段记录服务商 `reasoning_tokens`（缺失为 null）；包含在输出总量中，不重复计费，
  不保存或向前端展示思维链正文。
- 保留初稿、截断内容与实际用量。没有无界重试，也没有额外的第三次自动付费调用。
- SSE 累计传输预算随请求 Token 上限增长（最高约 64 MiB），避免协议元数据导致提前
  截断；单事件 2.5 MB、正文 2 MB 的内存保护不变。
