# PR #19 自动代码审查

## 范围与方式

在合并前审查相对 `main` 的改动，重点检查系统密钥与个人覆盖边界、模型分流和计费、
流式输出与取消、数据库迁移、草稿所有权与并发回写、发布权限、前端资产传递和启动器
进程身份校验，并结合现有及新增测试核对。此记录是自动代码审查，不代表独立人工批准。

## 发现并修复的问题

1. **P1：长任务覆盖较新的人工草稿。** 原回写使用结束时读到的最新版本加一，
   没有核对生成所基于的版本。现在将源版本传至保存逻辑，检查所有权、版本和状态，
   并使用带版本条件的原子 UPDATE 防止检查与写入之间的竞态。已修改、归档、发布或
   删除的草稿不被覆盖或重新创建；任务中的 AI 结果与实际用量保留供人工另存。
2. **P2：已验证资产未完整保存。** 已有草稿的 UPDATE 漏写暴力解与生成器，前端完整
   AI 结果载入编辑器时也漏传这两个字段。现在同步传递、保存本次结果中的资产，
   不再用旧资产填补本次缺失字段；版本快照与草稿保持一致。
3. **P1：草稿发布绕过日志可见性权限。** 新发布入口未复用普通题目写入的管理员
   权限限制。现在禁止普通用户经该入口改变日志公开状态，覆盖新建与更新两种路径。
4. **P2：任务完成状态早于草稿事务。** 现在将完成状态与草稿、版本、验证记录的保存
   一起提交，避免轮询已显示完成而关联草稿尚不可用。

## 回归验证

- 新增资产一致性测试，包含本次缺少 oracle/生成器时不沿用旧资产。
- 新增版本变更、归档、发布、删除、所有权不符以及读写之间竞态的保护测试；
  验证冲突后仍保留模型结果与用量，且不产生虚假的 AI 版本或验证记录。
- 新增管理员/普通用户 × 新建/更新的发布权限测试。
- 新增完整 AI 结果载入编辑器的资产传递测试。
- 本地 Windows 完整回归：166 passed、10 skipped（99.83 秒）；Ruff、mypy
  （27 个源文件）与差异空白检查通过。跳过项为平台相关评测测试，由 Linux CI 补验。
- 完整本地测试、静态检查和最新提交的 GitHub Linux CI 结果记录在 PR 审查评论中；
  不复用旧提交的 CI 结果作为新提交的合并依据。

## 非本次修复的运行边界

当前系统面向可信课程/本地使用，执行用户与模型代码的课程级进程限制不等同于生产级
隔离沙箱。公开注册和外部部署仍需加强账号滥用防护、共享模型额度及执行隔离。
独立 oracle 与 mutation tests 是有限验证证据，不是模型正确性或算法复杂度的数学证明。
真实模型测试会付费，本轮代码审查只使用本地测试与 CI，没有新增付费调用。
