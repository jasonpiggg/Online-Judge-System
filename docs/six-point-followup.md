# 六项界面与 AI 体验问题交付报告

日期：2026-09-05。对应用户六项反馈，基线为 `04946bc`（PR #27）。

上轮主要实现留在 `codex/ai-code-validation-layout` 工作区，尚未提交和交付。本轮继续核查、补齐边界处理、回归测试并完成 GitHub 流程；没有重写题库或改变权限、计分规则。

## 1. 正文到底指哪些，为什么之前看不出 16px

正文包括题目描述、输入输出说明、数据范围、提示、AI 回答、AI 审查意见和任务需求说明。导航、按钮、筛选框、表单标签、表格、徽章、时间与费用等辅助信息仍采用 14px。

上版虽然设置了 body=16px，但 `.assistant` 又被归入 14px 的 UI 规则，导致 AI 用户消息、任务结论等仍显得小。本轮修正容器继承规则和明确内容字号，正文使用 16px，行高约 1.7。代码编辑器独立默认 16px，仍可选择 14/16/18/20/24；示例代码、差异代码和其他 UI 字号没有一起放大。

验收：浏览器直接读取题面段落计算样式为 16px、提交按钮为 14px；1440/1024/390px 都检查。若旧页面未刷新，应刷新以加载新的构建文件。

## 2. 控件和文本挤在一起

根因是后追加的紧凑样式把编辑器工具栏、底栏和任务进度卡的左右 padding 覆盖成了 0。不是截图错觉。

修复包括：编辑器工具栏和底栏恢复桌面 22px、手机 15px 左右留白；任务卡恢复 20px/15px 内边距；标签与输入框间距 8px，按钮组和相邻操作至少 12px；编辑器、结果、AI 分区保持 28px 间隔。任务结论、用时、费用折叠区之间增加间隔和细分隔线。

共用样式覆盖题库、做题、提交、命题、资源、账户和管理页面。浏览器验收覆盖这些主页面、三档宽度、长题号、移动端导航和页面横向溢出；另加工具栏 padding/gap 的实际样式断言。

## 3. AI 代码没有 Diff，甚至一行覆盖整份正确代码

旧逻辑提取回答中的最后一个代码块，把任何片段当成可完整替换的代码，再直接覆盖编辑器。

现在所有可识别代码建议都先打开共用 DiffView：桌面并排、手机单列，红色删除、绿色新增，并支持切换布局。差异算法保留多个修改之间的未改行；Windows CRLF 与模型 LF 的差别不会把整份代码标成变化。大文件采用有界比较，避免大量测试数据耗尽内存。

只有用户明确要求代码、模型按协议标注“完整替换代码”、程序形态与长度符合保守检查，并且回答快照、当前代码和语言一致，才允许应用。提示/解释中的片段、日志代码块、不完整或失败任务、语言不匹配、旧快照均不能直接覆盖。审查打开后若继续编辑或切换语言，应用按钮停用。

应用后保留原代码并提供“撤销 AI 替换”；已继续编辑时禁止撤销覆盖新内容。复制失败给出手动复制建议。Prompt 升级为 v5：已全部通过时不得假设失败，不为提示/解释擅自生成替换程序，完整代码必须保留输入输出约定。

验收：单行片段不覆盖、完整代码差异/应用/撤销、审查期间改代码/切语言、CRLF、多个独立修改区；均有组件或真实 Chromium 的 mock 流程。

边界：程序形态检查不是编译器，也不证明算法正确。界面明确提示“尚未编译或评测”，仍须重新提交验证；未因该改动添加自动付费重试。本轮没有新增外部真实模型付费调用，因此不将 mock 输出宣称为模型质量实测。

## 4. AI 草稿生成内容裸露在页面上

本次任务需求、AI 回答、修改说明、仅审查结果、草稿已有审查、分阶段预览分别放入统一浅灰蓝容器，具有标题/标签、内边距、细边框和轻阴影。预览字段标注“题目描述/输入格式/输出格式/数据范围”，生成中的说明和代码版本提示也使用信息容器。

全站操作成功/失败消息采用容器样式；做题页保存失败改用 ErrorNotice，保留重试按钮。基础文本、标题和已有容器内的说明没有再重复套多层卡片。无内容的生成预览容器隐藏。Markdown 安全规则保持不变，代码和测试输入输出不经过公式改写。

## 5. 老题本地验证仍不通过

真实浏览器曾对“括号的秩序”点基础检查却收到完整验证资产缺失错误。检查保存的任务发现没有 `verification_mode`：8000 端口后端仍是升级前启动的进程，前端已加载新版本，后端却忽略了新参数。重启加载新后端后，同一旧题基础检查成功，报告为 2 个样例、5 个测试点。没有向正式题库发布验收草稿。

本轮额外完善：

- 三份内置旧题 `sum_2`、`brackets`、`prefix_sum` 均在隔离数据库实际执行基础检查，确认零模型 Token、原始测试数据不变。
- 基础检查允许没有参考解，但明确提示“没有自动核对输出”；有参考解必须通过所有样例与测试。
- 未闭合美元符号在手工旧题中作为可读排版警告，给出补全公式或转义美元符号的建议；损坏的公式括号、分隔符冲突、控制字符仍阻断。
- 完整门禁仍严格要求参考解、测试覆盖、错误解、独立 oracle 和随机生成器；缺失时指出补充位置，并提示手工题可先做基础检查。旧客户端无请求体仍执行 full。
- 检查前不再把尚未执行的公式/参考解项目显示为“已通过”；检查等级标题不再暗示必须完整验证才能发布。
- 验证失败状态与说明原子写入，显示“本地验证未通过”。失败页返回草稿修正，不再把“重新生成”偷偷变成付费命题。

边界：不承诺所有题无条件通过。结构错误、参考解错误、损坏公式、缺少完整门禁资产仍必须修复。基础检查通过不等于已经证明所有标准输出正确。

## 6. 点击进行中标签会跑到最左边

旧 upsert 每次把更新项放到数组开头；路由切换或保存状态更新都会触发重排。本轮更新已有项时保留原索引，只为新任务增加入口。状态、标题、路径刷新都不再移动旧标签。

验收：组件断言保持顺序；真实浏览器从右侧题目标签切回，比较切换前后全部标签标题数组，顺序一致。关闭入口、重新进入恢复、用户隔离和备份冲突逻辑继续保留。
