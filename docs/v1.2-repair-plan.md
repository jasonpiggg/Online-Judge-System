# Atelier OJ v1.2 修复方案

> 目标版本：v1.2.0<br>
> 基线：`main@ed22d20` / v1.1.0<br>
> 原则：先消除评分与数据安全风险，再改交互和视觉，最后扩展 AI 能力。继续使用 FastAPI、Streamlit 和课程规定 API，不在验收前迁移前端技术栈。

## 1. 修复目标

v1.2 需要解决四类问题：

1. **验收可信度**：基础模块保持不回归；AI 的题目合理性和测试有效性从“流程自洽”提升为有独立证据；实验报告补齐提交信息。
2. **用户任务流**：围绕选题、解题、提交、复盘和命题组织页面，减少装饰性内容和页面跳转。
3. **AI 深度融合**：AI 从独立侧边栏页面变为题目编辑、测试点设计、题目审查和提交复盘中的能力。
4. **稳定性与维护性**：改善刷新恢复、前端错误处理、状态同步、死代码、测试缓存和评测隔离。

## 2. 范围与非目标

### 本版本必须完成

- 修复实验报告个人信息、AI 证据和 PDF 可检索性问题。
- 保持课程 Step 1–6 及官方 API 行为不变。
- 完成新的视觉系统和题库、工作区、记录、编辑器的任务流改造。
- 新增可恢复的命题草稿、AI 任务历史、局部修改、版本差异和完整命题资产保存。
- 引入独立 oracle、随机对拍、边界生成和错误解杀伤率验证。
- 增加刷新/重登后的草稿恢复及前端异常兜底。

### 本版本不做

- 不迁移到 React/Vue，不改变课程要求的 Streamlit 前端。
- 不增加比赛、排行榜、社交等与本轮目标无关的模块。
- 不把课程级 subprocess 防护宣传为生产级沙箱。
- 不让学生侧 AI 接触隐藏测试输入、期望输出或其他用户源码。

## 3. 优先级与里程碑

| 阶段 | 优先级 | 预计投入 | 目标 |
| --- | --- | ---: | --- |
| P0 验收收口 | 最高 | 0.5–1 天 | 消除报告和 AI 证据中的直接失分风险 |
| P1 稳定性修复 | 最高 | 1 天 | 刷新不丢工作、异常可理解、状态与后端一致 |
| P2 视觉与核心流程 | 高 | 1–2 天 | 去除模板化 AI 视觉，缩短解题操作路径 |
| P3 AI 命题融合 | 高 | 2–3 天 | 让 AI 进入编辑器、测试点和审阅流程 |
| P4 AI 质量引擎 | 高 | 2–4 天 | 建立独立验证和可量化测试有效性 |
| P5 安全、测试与发布 | 中 | 1–2 天 | 隔离、回归、报告和发布证据闭环 |

建议按 P0 → P1 → P2 → P3 → P4 → P5 顺序实施。P0、P1 未完成前不进行大规模页面重构；P3 的数据模型先于 AI 页面开发。

## 4. P0：验收收口

### 4.1 实验报告

修改：

- 在 `docs/experiment-report.md` 填写姓名、学号、班级。
- 将“AI 质量与易用性 6 分”拆成：结构验证、独立验证、真实供应商验收、人工审阅四类证据。
- 若有真实模型密钥，选一个服务商执行 8–10 组基准命题；若仍无密钥，继续明确标注未验收，不将 mock 写成模型质量通过。
- 修复 PDF 字体映射，使中文能够正确复制、搜索和提取；重新逐页渲染检查。
- 更新截图：题库、桌面工作区、移动端、题目编辑 AI、测试点验证报告各至少一张。

验收标准：

- PDF 无空白身份字段、乱码、截断、重叠或模糊截图。
- 报告内每个数字都可追溯到命令输出、CI 或人工验收记录。
- `docs/scoring-checklist.md` 不再把未验证的真实模型质量标记为无条件完成。

### 4.2 真实模型基准集

建立 `tests/fixtures/ai_benchmark/`，只保存无密钥的需求与期望维度：

- 基础输入输出、字符串、栈/队列、排序、前缀和、二分、图搜索、动态规划等 8–10 类题目。
- 每项记录知识点命中、题意一致性、参考解正确性、测试点杀伤率、人工修改次数和费用。
- 真实调用作为人工发布门禁，不进入普通 PR CI，避免泄密和不可控费用。

通过标准：参考解验证通过率 100%；题意/约束不存在矛盾；每题人工评审记录完整；失败样本同样保留。

## 5. P1：稳定性与状态恢复

### 5.1 前端 API 客户端

涉及文件：`frontend/client.py`、`frontend/ui.py`。

修改：

- 根据 `Content-Type` 安全解析响应；HTML、空响应和损坏 JSON 转为统一的可读错误。
- 同时校验 HTTP 状态与 envelope `code`，两者不一致时标记为协议错误。
- 将连接失败、超时、认证过期、封禁、权限不足、限频、服务异常分开显示。
- 403 且后端 `msg` 表明账号被禁用时，清理 UI 登录态并显示重新登录/联系管理员提示。
- 为只读请求增加有限重试；提交、重测、AI 生成等有副作用请求禁止自动重试。

Edge Cases：代理返回 502 HTML、200 非 JSON、响应体为空、网络超时、后端返回未知字段、Session 在请求期间失效。

### 5.2 会话和草稿恢复

当前 `requests.Session`、源码草稿和当前 AI task id 只保存在 Streamlit `session_state`，浏览器刷新或直接打开子路径会丢失。

修复策略：

- 新增后端 `workspace_drafts` 表，按 `(user_id, problem_id, language)` 唯一保存源码草稿、更新时间和版本号。
- 新增：
  - `GET /api/workspace-drafts/{problem_id}/{language}`
  - `PUT /api/workspace-drafts/{problem_id}/{language}`
  - `DELETE /api/workspace-drafts/{problem_id}/{language}`
- 编辑器使用 800–1200 ms debounce 保存，不在每次按键时请求。
- 登录后恢复最近题目、语言和草稿；账号切换仍立即清除前一账号的本地瞬态数据。
- v1.2 先保证“刷新后重新登录即可恢复全部工作”。持久登录若要实现，单独评估同源反向代理和 HttpOnly Cookie 转发，禁止采用明文 localStorage Session ID 的快捷方案。

### 5.3 角色实时同步

- 每次应用入口调用本人资料接口刷新 `role`，不长期信任登录时缓存。
- 被降权后立即隐藏管理入口；被提升后无需退出重登。
- 管理员禁止无确认地封禁当前正在操作的自身账户；是否允许最后一个管理员被降权需给出明确规则。

验收标准：

- 浏览器刷新、Streamlit 重连、401 后重新登录均能恢复源码草稿和当前题目。
- 非 JSON 错误不会产生未捕获异常。
- banned 用户不会停留在不断出现普通 403 的死循环页面。

## 6. P2：视觉与核心任务流

### 6.1 视觉方向：Archive Lab / 档案实验室

用偏纸张、旧印刷和技术工作台的视觉语言替代通用蓝色 SaaS 模板。

| Token | 色值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F1EEE6` | 页面背景 |
| `surface` | `#FBF9F3` | 表单、工作区 |
| `ink` | `#292B27` | 主要文字 |
| `sidebar` | `#303A32` | 深苔色导航 |
| `accent` | `#C45F3F` | 朱砂色主操作 |
| `secondary` | `#74806F` | 辅助状态 |
| `border` | `#D8D1C3` | 分隔线 |
| `success` | `#47705A` | 通过 |
| `warning` | `#A87532` | 等待/提醒 |
| `danger` | `#A64B45` | 失败/危险操作 |

设计规则：

- 组件圆角收敛至 4–8 px，取消大面积浅蓝 Hero、渐变、玻璃拟态和漂浮阴影。
- 使用细分隔线、等宽题号、紧凑表格和小型状态印章。
- 主要按钮只使用一次 accent；次要操作用边框按钮或文本按钮。
- 正文保持至少 16 px，交互目标至少 44 px；状态不能只依赖颜色表达。
- 配色只在 `.streamlit/config.toml` 和统一 token 层定义，页面不再散落硬编码色值。

### 6.2 登录页

- 删除三段营销式功能介绍和大 Hero。
- 左侧改为最近系统公告、支持语言与运行状态；右侧保留紧凑登录/注册。
- 演示账号提示仅在开发环境出现。

### 6.3 题库

- 卡片列表改为紧凑题目表或行式列表。
- 增加用户维度状态：未开始、尝试中、已通过、最后得分、最后提交时间。
- 主操作根据状态显示“开始”“继续”“再次练习”。
- 搜索、难度、标签和完成状态使用同一筛选行；改变筛选立即重置分页。
- 题目数量扩大后将搜索、分页下沉后端，避免一次读取全部题目。

### 6.4 做题工作区

- 顶部增加返回题库、上一题/下一题、题号、限制和保存状态。
- 桌面端题面/代码比例可调；提交按钮和保存状态固定在编辑器工具栏。
- 最近评测显示为紧凑摘要，详细日志按需展开，避免结果把编辑器推到页面下方。
- 支持从历史提交载入代码，并明确提示会覆盖当前草稿。
- 移动端保持“题目/代码/结果”，提交后自动切换结果，但允许用户继续编辑。

### 6.5 提交记录

- 增加“全部通过/未全部通过”筛选，避免只有粗粒度 `success`。
- 表格直接显示最终得分和简短 verdict 摘要。
- 支持选取两次本人提交进行代码 diff。
- “查看公开日志”整合到可见提交条目，不再要求用户手输未知 submission id。

### 6.6 题目编辑器与管理中心

- 编辑器顶部展示六区完成度、未保存状态和验证错误数量。
- 每个标签显示错误徽标；点击错误跳转到对应字段。
- 更新、删除、封禁、提权、reset 均明确显示目标与影响范围。
- 删除前保留下载备份；reset 继续要求输入 `RESET`。

验收标准：

- 1440×900、1024×768、390×844 无页面级横向溢出。
- 登录、选题、提交、查看结果可只使用键盘完成。
- WCAG AA 级正文与控件对比度达标。
- 首屏不再出现与当前任务无关的大面积宣传区域。

## 7. P3：AI 命题融入题目生命周期

### 7.1 数据模型

数据库升级至 `user_version = 3`，升级前继续生成备份。

建议新增：

#### `problem_drafts`

- `id`、`owner_id`、`base_problem_id`
- `status`: draft / verifying / ready / published / archived
- `requirement`
- `problem_json`
- `reference_solution`
- `brute_solution`
- `generator_code`
- `review_json`
- `revision`、`created_at`、`updated_at`

#### `problem_draft_revisions`

- 保存每次人工或 AI 修改后的快照、来源、变更摘要和父版本。
- 支持回退和逐字段 diff，不覆盖历史版本。

#### `verification_runs`

- 保存参考解、暴力解、随机对拍、错误解、规模测试的结果和环境信息。
- 只保存有界诊断，不保存临时绝对路径。

扩展 `ai_tasks`：增加 `draft_id`、`parent_task_id`、`action`、`target_section` 和计价快照。

### 7.2 新增 API

- `POST/GET /api/problem-drafts/`
- `GET/PUT /api/problem-drafts/{draft_id}`
- `POST /api/problem-drafts/{draft_id}/ai-actions`
- `POST /api/problem-drafts/{draft_id}/verify`
- `POST /api/problem-drafts/{draft_id}/publish`
- `GET /api/ai/problem-tasks/`：任务历史与分页

所有新接口继续使用 `{code,msg,data}`，权限在后端判断。发布动作复用标准 Problem 校验与 POST/PUT 逻辑，不新增绕过入口。

### 7.3 编辑器内 AI 操作

在不同区域提供上下文相关动作：

- 题面：改写歧义、调整背景、检查输入输出一致性。
- 约束：补全边界、分析可行复杂度、发现矛盾。
- 样例：生成解释性样例并由参考解重算输出。
- 测试点：补充边界、规模、反例或针对某类错误算法的数据。
- 题目整体：降低/提高难度、生成同知识点变式、完整审查。

AI 结果必须显示字段级 diff，用户可逐项接受、拒绝或重新生成。禁止未经确认直接覆盖草稿或发布题目。

### 7.4 AI 页面重新定位

侧边栏“AI 命题”改为“命题中心”，只承载：

- 草稿和任务历史。
- 运行中任务、失败诊断和恢复入口。
- Token/费用统计、预算和模型设置。
- 基准测试结果与最近验证报告。

真正的生成与修改入口主要位于题目编辑器、题目详情和测试点实验室中。

验收标准：

- 可从已有题目进入编辑器，只让 AI 加强测试点，并逐项采纳。
- 刷新后可恢复草稿、任务、费用与版本历史。
- 参考解、暴力解、生成器、错误解和验证报告不会在载入普通编辑器时丢失。
- 发布前必须通过标准校验和明确的人工确认。

## 8. P4：AI 质量引擎

### 8.1 独立 oracle

命题产物必须包含：

- 清晰的问题规格和约束。
- 简单可信的暴力解，用于小规模 oracle。
- 目标复杂度参考解。
- 可复现的随机数据生成器，使用记录下来的 seed。

不能再用“模型生成的期望输出被同一模型生成的参考解通过”作为唯一正确性证据。

### 8.2 随机差分测试

- 对允许的小规模输入生成至少 200 组随机数据。
- 暴力解和参考解逐组比较输出。
- 失败时保存 seed、输入、两份输出和裁剪后的 stderr。
- 若题型不适合随机生成，要求提供题型专用 validator 或明确人工验证原因。

### 8.3 边界与变形测试

- 根据约束自动构造最小、最大、空值、重复值、有序、逆序、极端偏斜等边界。
- 支持 metamorphic properties，例如排列不变性、答案单调性、加法平移等。
- coverage 文本不能只由模型自述，必须引用实际 case id 和执行结果。

### 8.4 Mutation testing

- 除模型生成的错误解外，维护课程知识点对应的典型错误实现库。
- 输出每个测试点杀死了哪些错误实现，以及整体 mutation score。
- CE、RE、UNK 不计入有效卡错；若错误算法在无关输入上崩溃，应标记题目资产不合格。
- 初始发布阈值建议为典型错误实现杀伤率不低于 80%，并要求每类关键错误至少被一个用例命中。

### 8.5 规模与难度校准

- 使用 1×、2×、4× 数据规模运行参考解与慢解，记录耗时曲线。
- 不仅依赖静态复杂度文字；通过实际倍率辅助判断时间限制能否区分复杂度。
- 基准在 Linux runner 中执行，Windows 结果只作界面展示。

验收标准：

- 每个发布草稿有 oracle 对拍报告、边界报告、mutation score 和人工结论。
- 失败验证的草稿不能一键发布。
- 验证任务可取消，取消后回收所有子进程并保留已产生的有限诊断。

## 9. 学生侧 AI 辅助（P4 后半，可独立开关）

### 允许的功能

- 对本人提交的 CE、RE 和公开诊断给出解释。
- 根据题面和作者预设知识点提供三级 Socratic hints。
- 比较本人两次提交，指出修改影响和可能遗漏的边界。
- 在通过后推荐同知识点变式题或复习材料。

### 禁止的数据

- 隐藏测试输入和期望输出。
- 其他用户源码、用户名或提交细节。
- 管理员审计信息、模型密钥、服务端路径。

学生提示应以“引导定位”为目标，默认不直接生成完整答案；是否开放完整解答由管理员按题目配置。

## 10. P5：安全、性能与工程清理

### 10.1 Runner

- 课程验收保持现有接口，内部逐步迁移到容器/cgroup/seccomp。
- 默认禁网、只读基础文件系统、独立临时卷、非特权用户和进程数限制。
- 编译和运行分别配置 CPU、内存、文件大小、墙钟和输出限制。

### 10.2 并发与限频

- 将单 worker `asyncio.Lock` 限频改成数据库事务或集中式队列中的原子操作。
- 为提交、重测、AI 命题和验证分别设置并发上限。
- AI 任务增加用户预算、单任务 Token 上限和每日费用上限。

### 10.3 清理

- 删除未被引用的 `frontend/legacy.py`，先确认所有功能和测试已迁移。
- 为 SSE 大参数测试设置短 pytest 参数 ID，避免 `.pytest_cache` 产生数十 MB 的 node id。
- 统一前端 design token、状态文案和 verdict 映射。
- 删除重复页面函数和无法到达的兼容分支。

## 11. 测试计划

### 自动测试

- 模型：新增草稿、版本、验证报告和发布状态转换测试。
- API：新增任务历史、局部 AI 操作、草稿权限、恢复和并发测试。
- 前端：非 JSON 错误、banned、角色变化、重登恢复、编辑器 diff 和逐项采纳。
- AI mock：多轮修改、任务恢复、费用累加、预算终止、验证失败和取消。
- Runner：oracle 对拍、generator 超时/洪泛、mutation 批量执行和进程清理。

### 浏览器验收

- 1440×900、1024×768、390×844。
- 普通用户、管理员、banned 三种角色。
- 刷新、断线重连、Session 过期、账号切换。
- 题库 → 工作区 → 提交 → 复盘；题目 → AI 局部修改 → 验证 → 发布两条完整链路。
- 使用键盘和屏幕阅读器语义检查关键流程。

### 发布门禁

```bash
uv run ruff check src frontend tests scripts
uv run mypy src
uv run pytest --cov=oj --cov-branch --cov-report=json:coverage.json
uv run python scripts/check_coverage.py coverage.json
uv run pip-audit --local --skip-editable
```

后端行覆盖率继续不低于 90%，分支覆盖率不低于 85%。Linux CI 必须覆盖 Python/C++14 verdict、AI 本地 HTTP/SSE、差分验证和取消清理。

## 12. 数据迁移与回滚

- 数据库升级前自动创建 `pre-v3` 备份；迁移必须幂等并保留旧用户、提交、AI 配置和任务。
- `problem_drafts` 等新表只增加数据，不改变课程表的既有语义。
- Problem JSON 格式保持向后兼容；新增命题资产保存在数据库，不向题目 JSON 塞入课程未定义的大型字段。
- 视觉重构按页面拆分提交，可单页回滚；不要把数据迁移、AI 引擎和全站 CSS 放在同一 PR。
- 发布失败时回退应用版本并使用迁移前备份；禁止使用 reset 代替迁移回滚。

## 13. PR 拆分建议

1. `docs/release-evidence`：个人信息、评分表、PDF 字体和验收记录。
2. `fix/frontend-resilience`：API 错误、角色同步、草稿持久化。
3. `feat/archive-lab-theme`：design token、登录页和全局视觉。
4. `feat/problem-workflows`：题库、工作区、记录、编辑器交互。
5. `feat/authoring-drafts`：v3 迁移、草稿、版本和任务历史。
6. `feat/inline-ai-authoring`：局部 AI、diff、接受/拒绝和命题中心。
7. `feat/ai-quality-engine`：oracle、generator、差分、mutation 和规模测试。
8. `chore/v1.2-release`：安全、全量回归、浏览器证据、报告和版本发布。

每个 PR 均使用 Conventional Commits，经独立 CI 成功后合并；不在修复分支中混入无关功能。

## 14. Definition of Done

v1.2 只有在以下条件全部满足时才可发布：

- Step 1–6 原有 API、权限和 runner 测试无回归。
- 报告个人信息完整，PDF 可正确渲染、复制和搜索中文。
- 刷新/重登可恢复源码草稿、命题草稿和任务历史。
- 题库、工作区、记录和编辑器完成 Archive Lab 视觉与任务流验收。
- AI 可在编辑器内局部修改，并提供逐字段 diff 和人工确认。
- 命题资产包含参考解、暴力解、生成器、错误解和验证报告。
- 发布草稿通过随机差分、边界验证、mutation testing 和人工审阅。
- 真实模型基准结果如实记录；没有密钥时明确保留“未验收”结论。
- Ruff、mypy、pytest、覆盖率、依赖审计、Linux CI 和三档浏览器验收全部通过。
- 工作树无死代码、无意外大文件、无密钥和运行数据进入 Git。
