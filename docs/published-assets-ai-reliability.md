# 发布资产与 AI 稳定性修复（2026-09-09）

## 发布与恢复

参考解原本已生成且保存在成果草稿中。丢失发生在发布和重新编辑之间：题库只保存课程
Problem 字段，新编辑草稿也只复制这些字段。现在 SQLite v9 单独保存发布资产快照，
记录来源草稿、revision、发布时完整题目内容和时间；升级前沿用自动数据库备份。

用户明确选择向所有已登录用户开放发布资产，包括参考解、独立解法、生成器、错误解、
覆盖说明和公开审查文字。个人命题需求、未发布草稿、会话、模型配置和费用不包含在其中。
课程题目接口保持原字段，`GET /api/problems/{id}/assets` 提供独立读取入口。

资产状态：`current` 当前内容匹配；`stale` 题目已修改，资产需要复核；`missing` 没有来源；
`ambiguous` 多个历史发布草稿内容匹配但资产不同，需要选择来源。新编辑草稿只自动带入
唯一且匹配的资产，并清除原验证报告。已有草稿不被覆盖；两个前端均提供差异预览和
“采纳并保存资产”，通过原有 revision CAS 保存当前编辑内容并失效旧验证。

旧题通过已发布草稿的完整题目内容匹配恢复，不能仅凭题号选最近草稿。资产有分歧时
展示多个来源供选择；不会自动重新调用 AI。删除题目保留资产清理标记，阻止同题号
重建后恢复旧资产或复用删除前的编辑草稿；旧草稿自身仍保留。重置清理资产表。
发布草稿状态与资产快照在同一事务中提交；题目文件使用原子替换，读取时核对内容，
不把文件与资产不匹配的状态当作当前有效资产。跨 SQLite 与文件系统没有分布式事务；
进程崩溃造成的不匹配会显示缺失或待复核，不伪造验证通过。

## 交互与模型修复

Streamlit 发送成功后在下一次渲染前清空输入；发送失败保留原文和幂等键。
快捷提问保留未发送的手写草稿，选项不重置。浏览器已覆盖发送、刷新和资产恢复。

全面审查使用实际 Patch Schema，排除受保护字段与缺失资产，避免完整候选 Schema
诱导模型补写 coverage。定向修复明确嵌套字段层级；仅在允许范围内，将无冲突的
顶层 samples/testcases 归入 problem，再执行原有白名单和严格校验。
参考解失败反馈增加最多三组输入、期望输出、实际输出及诊断，并限制文本大小。
四分钟总预算、最多一次定向修复、独立对拍和错误解质量门禁保持不变。
